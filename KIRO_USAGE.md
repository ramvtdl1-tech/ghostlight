# Actual Kiro development record

Date: November 25, 2026 (IST).

The initial Ghostlight application was built using Codex. Kiro CLI was subsequently installed from the official kiro.dev installation endpoint and authenticated by the account owner. This document describes only the work actually performed with Kiro.

## Task and context

Kiro read the existing `.kiro/specs/ghostlight` requirements, design and tasks, steering guidance, domain logic, UI and tests. It was asked to add editing of saved scenarios while preserving the scenario snapshot inside previously created exercises. The task explicitly prohibited credentials, parent directories, network, package installation, commits and pushes.

## Kiro implementation

Kiro added the `editScenario` domain function, library Edit buttons, pre-filled edit dialog, create/edit state handling, validation and cancel reset. It added four regression tests covering preserved scenario identity, unchanged session snapshots, unknown IDs and invalid fields, and updated documentation/specs.

Kiro ran all 14 tests and JavaScript syntax checks successfully. Codex independently ran the tests, checked the browser edit/save flow, and synchronized `workspace.html` into the served `index.html` during integration. Browser verification showed a modified scenario name persisted in the library.

## Workflow findings and limits

The first headless attempt could read but had incorrect tool-trust names and could not write. The resumed CLI run used the actual read/write/shell tool names and completed the implementation. We do not claim Kiro authored the initial application, that we used Kiro Crew, MCP, hooks, property-based tests, or multiple Kiro products. Existing specs and steering were originally written by Codex and supplied as context to Kiro; they were not originally generated by Kiro.

This is evidence of actual Kiro usage, not a guarantee that judges will consider its extent sufficient. The official rules leave that decision to the judges.
