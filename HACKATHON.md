## Category and judging strategy

Selected: Costume Contest. The haunting supports the task: ghost incidents, dark trace console, containment status, and an incident journal make simulated failure approachable. Other categories are Resurrection (obsolete tech), Frankenstein (unexpected integrations), and Skeleton Crew (a template demonstrated with two separate apps). Do not claim those fit by default.

Five criteria each carry 20%: potential impact, technological implementation (effective Kiro use), design, innovation, presentation. Ghostlight demonstrates a real training use case, functional state transitions, responsive design, and a complete export loop. Three deterministic scenarios are educational exercises, not a production observability service or AI diagnosis system. Kiro implementation credit remains unfulfilled.

## Submission description draft

Ghostlight turns software outages into a safe, spooky rehearsal. Small teams can investigate a phantom deploy, a saturated connection pool, or a retry storm without touching production. Each exercise provides a symptom, evidence-gathering action, plausible interventions, immediate feedback, and prevention guidance. A local incident journal becomes a downloadable postmortem. The browser-only architecture makes the demo accessible without credentials or API costs. The current version offers three authored exercises, not live telemetry or automated diagnosis.

## Demo script (about 2 minutes 30 seconds)
